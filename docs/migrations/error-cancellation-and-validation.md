# Error, cancellation, and validation contracts

These changes belong to the next minor release. Update error matching before
upgrading; this batch does not select a release version.

## Cancellation at execution boundaries

`StandardPipeline`, `AnyStandardPipeline`, and `DynamicPipeline` check task
cancellation at entry, between middleware, and before the handler, including
empty and cached chains. Their outward cancellation error is
`PipelineError.cancelled(context:)`. A handler's native `CancellationError` is
normalized to that case; an existing typed cancellation keeps its context.
An unrelated thrown error retains its identity even if the task is cancelled.
These boundaries do not preempt arbitrary handlers or replace successful results
after work has settled.

`CommandContext.getCancellationReason()` returns diagnostic metadata. The pipelines record
`.userCancellation` only if no more specific reason is already present. Reusing
a context with an old reason does not cancel a live task.

The throwing acquisition APIs on `SimpleSemaphore`, `AsyncSemaphore`, and
`BackPressureSemaphore` now throw `PipelineError.cancelled`. The timed Boolean
`AsyncSemaphore` overload still returns `false` on cancellation. Permit ownership
and settlement behavior are unchanged. Direct APIs outside these boundaries,
including admission gates and test helpers, may still throw native cancellation.

When accepting errors from both library pipelines and other async operations,
recognize both cancellation types:

```swift
import PipelineKit

func isCancelledExecution(_ error: any Error) -> Bool {
    if error is CancellationError { return true }
    if case .cancelled = error as? PipelineError { return true }
    return false
}
```

`PipelineCancellationBoundaryTests`, `SimpleSemaphoreErrorContractTests`, and
`SemaphoreCancellationErrorContractTests` cover these execution and acquisition
contracts, including permit reuse after cancellation.

## Retry, health, and breaker policies

Retry, resilient retry, health, and breaker middleware recognize both direct
cancellation types before invoking custom error predicates. Cancellation is
never retryable or a service failure, even if a custom predicate returns `true`.
Retry loops check cancellation before the next attempt and during backoff.

By default, health and breakers exclude these direct typed `PipelineError` cases:

| Category | Cases |
| --- | --- |
| Command and security policy | `validation`, `authentication`, `authorization`, `securityPolicy` |
| Rate and admission | `rateLimitExceeded`, `circuitBreakerOpen`, `bulkheadRejected` |
| Legacy resilience categories | `resilience(.bulkheadFull)`, `resilience(.circuitBreakerOpen)` |
| Back pressure | `backPressure(.queueFull)`, `backPressure(.commandDropped)`, `backPressure(.memoryPressure)` |

Ignored outcomes are neither successes nor failures: they do not reset health
streaks or add samples to its health window. They can still emit an execution
failure event. Timeouts and unknown downstream failures still count by default.
Existing time-window expiry and recovery rules remain in effect.

Custom predicates can override classification of noncancellation errors.
Health configuration adds an optional `errorEvaluator` parameter:

```swift
import PipelineKit
import PipelineKitResilience

let healthPolicy = HealthCheckMiddleware.Configuration(
    errorEvaluator: { error in
        // This application's explicit policy ignores its own validation errors.
        if case .validation = error as? PipelineError { return false }
        return true
    }
)
_ = healthPolicy
```

Classification of `PipelineError` uses direct cases, not payload text or recursive
unwrapping of `wrapped` or `retryExhausted`. Those wrappers need an explicit
noncancellation predicate if they carry additional meaning. Retry and breaker
policies retain their existing description-based timeout fallback for foreign
errors; health treats unknown errors as failures by default.
`ResilienceErrorPolicyTests` covers the default case matrix, custom predicates,
retry cancellation, and abandonment of cancelled half-open probes.

## Typed middleware failures

Update catches that previously inspected generic middleware names or raw crypto
errors generated by middleware:

| Producer | Error now emitted |
| --- | --- |
| Breaker rejection | `PipelineError.circuitBreakerOpen(resetTime:)` |
| Ordinary or partitioned bulkhead rejection | `PipelineError.bulkheadRejected(reason:)` |
| Ordinary or partitioned bulkhead queue deadline | `PipelineError.bulkheadTimeout(timeout:queueTime:)` |
| Encryption middleware's encryption/decryption failure | `PipelineError.encryption(reason:)` |

An open breaker's `resetTime` is the deadline observed when it rejected the call.
A busy half-open breaker has no known reset deadline and returns `nil`.
The redundant bulkhead error factories that shadowed the typed enum cases are
removed; the typed cases retain their construction syntax.

Encryption middleware preserves downstream handler errors. Recognized native or
typed cancellation is propagated as typed cancellation before crypto-failure
mapping; partial-decryption mode cannot turn cancellation into success.
`EncryptionErrorContractTests` checks those distinctions. The ordinary-import
Consumer's `error-contract` mode also exercises public pipeline and policy
composition without test-only imports.

## Test support and validation

`TimeoutTester.withTimeout` creates a `PipelineError.timeout` when its own timer
wins. Operation errors, including operation-thrown timeouts, pass through unchanged.
`expectTimeout` returns `true` only for that
owned deadline; operation-thrown timeout or cancellation returns `false`.
Both helpers cancel and join the losing child. Work that ignores cancellation
can delay return indefinitely, so these helpers are not process watchdogs.
`TimeoutTesterContractTests` includes an explicitly released, cancellation-ignoring
operation to verify settlement.

All `TimeoutTester` duration inputs must be finite, nonnegative, and representable
in nanoseconds. Derived durations must also fit: `operationThatWillTimeout(after:)`
adds one second, while `operationThatCompletesJustInTime(before:)` uses 80 percent
of the supplied duration. Invalid inputs fail a precondition before conversion.
The numeric validation driver covers every entry route in isolated processes.

Use `try await synchronizer.waitForSignal(checkpoint)` when successful return must
mean a signal was received. It throws native `CancellationError` on task
cancellation or `reset()`. The compatibility method `wait(for:)` returns on any
of signal, cancellation, or reset, so its return alone is not an acknowledgement.
`TestSynchronizerContractTests` covers registration, cancellation, reset, and
signal behavior. A signal and cancellation racing after registration are settled
by the actor's processing order.

Mock logging and metrics getters now take snapshots under the same lock as their
writers; `MockSnapshotContractTests` exercises concurrent reads and writes under
Thread Sanitizer. The stress CI job uses the checked test runner, so failing
tests, failed discovery, and empty selections fail the job.

See [validation commands](../../Scripts/validation/README.md) for the public
Consumer, numeric probes, sanitizer checks, and external watchdog.
