# Implementation decisions

Chronological controller rulings made while executing the approved batch. Each retains its reason and the cost if the decision is wrong. These decisions do not authorize a push, merge, release, or expansion of the selected finding count.

1. preserve alphanumeric task IDs and extract their exact task sections with a bounded Python parser — the skill task-brief script only accepts numeric headings and failed on V01 — cost if wrong: an incomplete brief could omit a requirement; each extracted brief is checked against its source section.

2. apply the approved targeted checks at each task and the complete appropriate unit suite once per substantive task; reserve expensive Release/performance/platform matrices for their owning tasks and I01 — avoids redundant broad runs while retaining required evidence — cost if wrong: an unrelated configuration regression may be found at integration rather than immediately.

3. This preserves the filter contract rather than restricting accepted patterns.

4. subsystem tasks that require a migration draft will create/extend docs/migrations/first-stabilization-batch.md, and I01 will complete/compile that same file — this is I01's designated destination and avoids divergent drafts — cost if wrong: partial intermediate guidance may need revision; it remains explicitly unverified until I01 compiles examples.

5. Controller sent this bounded contract check to the implementer; no crypto redesign or separate SCP-09 scope expansion.

6. R01 nonpositive queue timeout allows immediately available capacity but times out if waiting is required; pre-observed cancellation still wins — timeout bounds queue waiting, and this avoids a new package-only invalid-duration error absent from the design — cost if wrong: callers expecting zero to reject even immediate capacity would need a boundary adjustment; wrappers retain their own configuration validation. Add focused boundary tests.

7. add scoped V04 immediately after O01 review to repair the execution watchdog’s observed escaped-descendant cleanup gap — the approved spec requires bounded hang probes, and root-group termination did not contain XCTest — cost if wrong: one additional implementation/review task and process-inspection overhead; safe identity checks, an unrelated sentinel and a real isolated XCTest probe constrain signal risk. This is validation support, not a new main audit finding; 37 selected and 47 deferred remain unchanged. No further deliberate hang mutants until V04 acceptance.

10. explicitly list R02 as a dependency and its shared BulkheadAdmissionConservationTests file in R03 — the existing R03 requirement to run the same matrix across all three wrappers necessarily extends the R02 fixture, but its file/dependency list omitted that work — cost if wrong: one unnecessary test-adapter edit; no production scope or finding count expansion, and the R03 review must verify the existing two-wrapper cases remain intact.

11. allow narrow internal admission-snapshot and injected-gate initializers in R02 — ordinary bulkhead has no public live-state observation and deterministic timeout/cancel testing should reuse the design-approved R01 clock seam — cost if wrong: maintaining a nonpublic test interface or testing a mismatched injected configuration; fixtures must match public configuration, final wrappers keep no duplicate counters, and public-path coverage remains. Old observation-only seam must be identified in red evidence, not called pristine production. Legacy has no public timeout, so timeout rows are explicitly ordinary-only while shared capacity/success/throw/cancel/handoff rows cover both; no new legacy timeout API.

12. bound ordinary bulkhead positive finite queue timeouts at 86,400 seconds and cache the validated Duration; normalize all finite nonpositive values directly to zero, with nil unbounded — an explicit conservative queue-wait contract avoids unchecked conversion and provides immediate Duration deadline-addition headroom without rewriting R01 — cost if wrong: finite waits over 24 hours become invalid; callers must revisit their policy or use unbounded waiting with application cancellation, which is not an equivalent finite deadline. This is a deliberate behavior break, not a Swift intrinsic limit. Document the public contract, migration and I01 Breaking entry. The source proof covers conversion and immediate Duration addition, not arbitrary clock/runtime extrema; tiny positives retain nearest-attosecond rounding.

13. carry R02’s checked timeout policy/helper and mechanical boundary matrix into R03 — PartitionConfig.queueTimeout is also TimeInterval and its UInt64(timeout * 1e9) conversion is a second instance of this boundary class — cost if wrong: finite partition waits over 24 hours also become invalid. Document and independently review the same behavior break, using one internal helper and tests for both timed wrappers. Legacy has no timeout API; R02 does not edit partitioned production early.

14. R03’s public-wrapper timeout/sibling test uses staggered arrival times under the partition’s single timeout, so B expires while C has a later deadline; the cancellation variant uses a nil-timeout partition — the original timed-B/untimed-C description cannot be expressed through one public PartitionConfig — cost if wrong: it does not test mixed per-waiter timeout policies in this wrapper, which the API does not support; R01 already covers that gate-level combination. No new public timeout override or misleading test-only policy is introduced.

15. a 100% partition reserve retains the exact Int capacity, including values beyond Double’s exact-integer range; fractional percentages preserve the established truncated Double product with safe clamping — a rounded-down accidentally lendable slot or a conversion trap contradicts full-reserve semantics — cost if wrong: callers relying on an accidental spare slot at very large capacities lose that borrowing behavior and must choose an explicitly smaller reserve. Int.max/Int.max-1 tests are bounded evidence, not an exhaustive numeric proof; the full-reserve equality is also derivable from adjacent clamping logic. Original implementer may commit the validated state without another broad run.

16. StatsD close marks closed and rejects new recording immediately, cancels owned timer/startup, then joins startup settlement and closes any late-produced transport before returning — resource ownership and deterministic cleanup require settlement, consistent with the design’s no-hard-deadline constraint — cost if wrong: a cancellation-insensitive injected factory can delay close indefinitely; callers needing a bound require a cooperative dependency. Repeated/concurrent close must share terminal ownership; fixtures release the held factory after observing the closed state and then join all work.

17. allow R04 an internal default-true periodic-check scheduling seam alongside the injected clock, with public initialization always enabling periodic checks — deterministic probe completion must not race automatic initial checks or create additional background loops, while R-F06 lifecycle is unselected — cost if wrong: recovery fixtures could miss an automatic-monitor interaction; retain existing health/check tests and source-trace public/default construction routing, and keep lifecycle validation explicitly open.

18. allow R05 an internal Date provider through RateLimiter and its four existing algorithm types — the required near-window controls otherwise depend on real epoch boundaries and adaptive refill, making deterministic validation impossible without sleeps — cost if wrong: added clock plumbing could alter timing or miss a lookup path; preserve public signatures/default Date behavior and algorithm policies, and explicitly cover all four affected clock paths in the new strategy/boundary matrix, preserving any existing algorithm tests actually present.

19. resolve R06 wrapped-error wording in favor of structural classification for every PipelineError: non-timeout wrapped/retryExhausted payloads are other, typed cancellation retains ordinary unknown policy, and foreign wrappers/native cancellation retain existing fallback/evaluator precedence — a wrapped text exception would defeat the explicit no-payload-text timeout contract — cost if wrong: applications relying on the word timeout inside non-timeout PipelineError payloads lose accidental retry/selective-breaker classification and must supply an explicit evaluator; document that behavior change and test both preserved controls and changed text cases.

20. extend the final release-under-lock correction to the known CommandContext arbitrary-value storage retirement paths as well as every SimpleCachingMiddleware discard path — the owner requires a mechanical regression for a repeated defect class, and CommandContext is a second source-confirmed instance in an already-touched selected component even though the risk predates C03 — cost if wrong: a wider Core lifetime change can affect mutation ordering, atomic merge guarantees or per-operation cost; retain atomicity, avoid copying the whole storage on every small mutation, add a public-path retirement/reentry matrix, and rerun the affected validation. This is bounded adjacent work, not closure of any of the 47 deferred IDs or a repository-wide callback-safety claim.
