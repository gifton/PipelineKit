### Important — FINAL-RV-F1: cache payload destruction can reenter a held storage lock

**Locations:** `Sources/PipelineKitCache/LRUStorage.swift:61` (new weak predecessor), `:206`–`:209` (clear releases ownership); `Sources/PipelineKitCache/SimpleCachingMiddleware.swift:183`–`:186` (`clear` holds `NSLock` across that release), `:212`–`:214` (`getStats` reacquires it).

**Trigger:** Store two Sendable reference-type results in a public `SimpleCachingMiddleware`, let the cache become their last strong owner, and give each result a deinitializer that synchronously calls `getStats()` through a weak cache reference. Call `clear()`. A weak reference avoids a user-created cache/payload retain cycle; neither unsafe conformance nor an internal/testable cache API is required.

**Consequence:** `clear()` releases a payload before unlocking. Its deinitializer enters `getStats()`, which waits forever for that same nonrecursive lock. The outer clear cannot return, and other operations using this cache lock cannot progress. This is ordinary cleanup/reentry through public APIs, not a claim of arbitrary malicious callback behavior.

**Baseline distinction:** At the original baseline the two-node forward/backward cycle retained both payloads: the same clear returned with zero entries and **zero releases**. The final non-reentrant control returns and releases **both** payloads. The final reentrant case reaches `BEFORE-CLEAR`, `PAYLOAD-DEINIT-ENTER one` and `BEFORE-GET-STATS one`, but never reaches `AFTER-GET-STATS`, `AFTER-CLEAR` or `COMPLETED`. After five seconds the reviewed watchdog terminates the process: root `-15`, runner `124`, cleanup settled, no survivors or inspection errors. Thus fixing the leak really arms this previously masked multi-entry clear path. The older leak is not a working baseline ownership contract.

**Required repair scope:** Retain/detach removed cache entries until after the middleware's lock is released. Apply the same ownership rule to all cache discard paths: explicit clear; lookup expiration (`SimpleCachingMiddleware.swift:145`–`:158`); expiry sweep (`:193`–`:204`); insertion eviction and same-key replacement (`:167`–`:176`, `LRUStorage.swift:169`–`:184`). Public concurrent misses can reach same-key replacement even when ordinary hits bypass insertion. Expiration locals must have an explicit lifetime through unlock, rather than depending on an optimizer's last-use choice. Preserve LRU order, TTL behavior, capacity, and the weak predecessor repair. Merely using a recursive lock would allow reentry into partially mutated state and is not sufficient evidence of a correct fix.

Add a mechanical public-path regression matrix using cached reference results whose destructor reenters a read operation, with post-mutation state and after-return sentinels. Cover clear with multiple nodes, both expiration routes, eviction after promotion, and same-key replacement; retain the existing ordinary release/container-drop controls. Run the scoped matrix bounded in Debug and Release, join all fixture work, and verify weak witnesses and consistent stats. Only the multi-entry clear path was dynamically probed by this review; the other discard sites are the required same-class source challenge, not claimed separate runtime reproductions. This repair scope is **the cache class**, not a claim that arbitrary-value destruction under locks is solved repository-wide. The pre-existing CommandContext instance is explicitly retained for controller adjudication below.

## Strengths and plan alignment

The implementation substantially follows the approved architecture. Builder entries preserve raw middleware identity and effective order; DynamicPipeline makes selection/publication indivisible within its actor; diagnostic and Metrics configuration snapshots retain retired callback ownership beyond their locks. Encryption removes the retained-command escape hatch and binds ciphertext to one captured key pair. All four cache APIs require explicit semantic identity with unambiguous type framing. Admission uses one lease owner across ordinary, legacy and partitioned wrappers. UDP terminal transitions remove continuation records before resumption, and StatsD has one startup-generation owner.

The tests generally check behavior rather than mere non-crashing: invalid security routes assert zero handler entries, cache cases assert exact ownership/hit counts, bulkhead cases compare live handler occupancy with lease state, and transport tests withhold/duplicate/late-deliver callbacks. Acknowledged gates and fixture joins materially improve the evidence. V04 separately repairs the validation watchdog's observed-descendant ownership; V05 removes unsafe fixture sharing without pretending to prove the old signal11's exact cause. The final O04 upper-bound check precedes `Duration.components` narrowing, and its signed-quotient extremes are in both final full suites.

The weak LRU change meets its narrow planned predecessor change but misses the reasonable lifetime/reentry expectation exposed by that change. Following the plan is not enough to approve this regression. The 24-hour positive queue-timeout policy, required capabilities, whole-command encryption, explicit keys and async Metrics configuration are documented breaking choices accepted by the controller; they are not downgraded or rejected merely for being breaking.

## Gate reachability and ownership scrutiny

- **Restored builder stages:** Named/plain/array/explicit families now all reach dispatch.
